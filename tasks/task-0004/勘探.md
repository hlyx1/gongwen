## 二、八项逐项勘探

### 0001｜三级标题序号后英文句点字体

- **预览现状**：`.a4-h3` 内整句单 span——快照实证 `<p class="a4-h3"><span class="a4-h3-inline">1.加强组织领导。</span><span class="a4-paragraph-inline">要压实各方责任。</span></p>`（previewStructure.test.tsx.snap）。序号「1」与句点「.」均随 a4-h3-inline（仿宋三级标题字体，A4Page.css:155-157）。
- **导出目标**：`splitHeading3NumberDotRuns`（runs.ts:94-119）拆为 [序号(heading3), '.'(bodyPunct 正文字体四槽), 内容(heading3)]；bodyPunct 四槽全正文字体（fonts.ts:26-29 `bodyPunctQuad`），字号随三级标题（fonts.ts:137-144）。
- **翻转后预览侧断点（接线必做，不是纯翻开关）**：`renderHeadingRuns`（renderContentFlow.tsx:99-141）现状「首 run→a4-h3-inline，后续 run 恒 a4-paragraph-inline」。翻转后 preview runs＝[序号(h3), '.'(bodyPunct), 内容。(h3), 剩余(body)]——直接套现状逻辑会把「内容。」误染 a4-paragraph-inline（正文字体），错向。需改为按 `run.role` 映射类名：`heading3→a4-h3-inline`、`bodyPunct→正文字体类`（新类 `.a4-body-punctuation`，或复用 a4-paragraph-inline——两案见 §三）。
- **AI 高亮耦合（红线交互）**：现状首 run 整体查 seq=1（renderContentFlow.tsx:109-124）。拆分后首 run 只剩序号数字——seq=1 查询域必须改为「首句全文本域」（聚合到「。」边界的 runs），否则三级标题首句高亮退化为只罩序号。切句正则与 sentenceId 格式本身不动（aiHighlight.tsx:41/:62 冻结项）。
- **变更前后差异（用户可感）**：预览中「1.」的半角句点从三级标题字体（仿宋，跟随 h3 字体设置）变为正文字体（仿宋_GB2312 跟随正文字体设置）。默认配置下两者同字体（h3 默认仿宋_GB2312＝正文仿宋_GB2312）——**默认视觉零差异，仅当用户把 h3 或正文改成不同字体时可感**。

### 0002｜页码纵向位置（预览 bottom 4.2% vs 导出 7mm）

- **预览现状**：`.a4-footer { bottom: 4.2% }`（A4Page.css:343-351）。换算：预览 72dpi（Preview.tsx:43 注释），页高 297mm≈842px，4.2%＝页码元素**底边**距页底 ≈12.5mm。
- **导出侧机制与值**：`pageNumber.vertical＝{ footer-spacing-before, beforeTwips: 397 }`（constants.ts:88-91，`PAGE_NUMBER_GAP_TWIPS = cmToTwip(0.7)`）；docxBuilder.ts:357-378 译为页脚段落 `spacing.before=397`。**注意 docx 库 sections 未显式设 footer margin，用库默认 708 twips（12.49mm，node_modules/docx/dist/index.mjs:14246-14247）**——页码绝对位置＝708＋397＋行高的复合，7mm 是「段前距」不是「距页底距离」。
- **换算真相（重要）**：两侧机制不同（百分比底距 vs 页脚段前距），且 OOXML w:footer 锚定语义（页脚顶线还是底线距页底）决定换算结果在 **4.2%～8.2%** 区间摆动（三种解读分别得 ≈4.21%/6.57%/8.22%）——**字面「4.2% vs 7mm」的直觉差被夸大，实际视觉差可能在 1mm 量级甚至为零**。机械换算不可靠，对齐目标值必须以导出 docx 在 Word/WPS 的实测位置定标（人工步骤），再把定标值写回开关 preview 分支与 CSS。
- **接线方案两案**（挂起待裁，默认案 A）：
  - 案 A（CSS 单源改值，默认）：保持预览 css-bottom-percent 机制，仅更新 `bottomPercent` 定标值＋A4Page.css 同步。结构快照零变化；弱点＝开关值与 CSS 值两处人肉同步（现状架构本就如此——A4PageNumber.tsx 注释明言「CSS 单源」）。
  - 案 B（组件消费决策参数）：A4PageNumber 读 `layout.pageNumber.vertical` 输出内联 style。单一真值更彻底，但预览结构快照中含页码的条目全变（style 属性出现），且 twips→px 换算进组件。
- **变更前后差异**：页码上下位置小幅移动（量级 ≤7mm，定标后确定）；默认 72dpi 预览下约 0～20px。

### 0003｜版头红色分隔线粗细与间距

- **预览现状**：`.a4-header-separator { border-bottom: 2px solid #e00000; margin-top: 8px }`（A4Page.css:382-386）。

- **换算（可靠）**：预览 72dpi 下 1pt＝1px → 目标值 **border-bottom: 1.875px；margin-top: 4px**（Chrome78 支持亚像素 border 渲染）。

### 0004｜全角句点「．」的三级标题序号拆分

### 0022｜时间冒号字体分段（预览接线，DOM 方案需裁定）

- **决策层现状**：导出分支 `timeColonSplit='split'` 已生效——正文/标题/主送/署名/日期/备注中 `9:00` 的半角冒号拆为 bodyPunct run（layout/index.ts:188-225，正则 runs.ts:16）。预览分支 `'no-split'`：这些节点整段单 run。
- **预览侧断点（接线必做）**：renderParagraphBlock 对非标题段落直接 `blockText(block)` 拼接全部 run 再整段渲染（renderContentFlow.tsx:61-65、:213-217）——即便翻开关，拆出的 runs 被拼接抹掉，无分段效果。需为正文族引入 run 级渲染。
- **DOM 处理候选方案（必答，挂起待裁）**：
  - 案一（全 run span）：每 run 包 `<span className={ROLE_CLASS[run.role]}>`，AI 高亮嵌套在内。结构一致性好（与附件渲染 renderAttachmentContent 先例同构，renderContentFlow.tsx:149-168）；代价＝**所有正文段落无论有无时间冒号都多 span 层**，previewStructure 快照大面积变化，且无 AI 结果时正文不再是无 span 纯文本子节点（现状快照特征）。
  - 案二（仅标点 span，最小 DOM）：runs 中非 bodyPunct 的同宿主 run 合并为纯文本，仅 bodyPunct run 包标点类 span——无时间冒号的文档 DOM **零变化**（快照只有含「9:00」的样例条目变）。代价＝实现稍绕（合并逻辑），AI 高亮与标点 span 交叉时（句子跨冒号）需句子内再切 run。
  - 两案共同红线：sentenceId 冻结——切句输入文本与 `nodeType-lineNumber-localSeq` 格式不动（aiHighlight.tsx:41/:62）；**跨 run 句序号连续性**是共同难点：`renderSentenceHighlight` 的 `sentenceSeqInNode` 每次调用从 1 起算（aiHighlight.tsx:59），按 run 分段调用会使后续 run 内句子的 seq 错位（sentenceId 冻结要求句序号在节点内连续）——需把句切分提升到节点级、或给句渲染传 run 前累计句数偏移（扩展调用约定但不改切句正则与 id 格式）。
- **变更前后差异**：预览中「9:00」「14:30」的半角冒号从宿主字体（正文仿宋语境下西文槽为 TNR——冒号半角字符落入 ascii 槽）变为正文字体四槽（仿宋）。默认配置下：正文段落西文默认 TNR，冒号拆出后变仿宋——**默认即可感**（冒号字形 TNR→仿宋，衬线差异细微）。
