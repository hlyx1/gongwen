## 一、0029 现状：AST 类型与全库消费点

### 1.1 类型定义现状（src/types/ast.ts）

- `NodeType` 为 13 成员字符串枚举（ast.ts:2-27）。
- `DocumentNode` 是**单一扁平 interface**：`{ type: NodeType; content: string; lineNumber: number }`（ast.ts:30-35）——`type` 未判别，任何枚举值都可塞进同一形状。
- `AttachmentNode extends DocumentNode` 加 `isMultiple/items`（ast.ts:46-52）；`TableNode extends DocumentNode` 加 `header/rows/columnCount`（ast.ts:65-73）。两者是仅有的「带专属字段的子类型」。
- `GongwenAST = { title: DocumentNode[]; body: DocumentNode[] }`（ast.ts:76-80）。
- 封闭化改法（实施细节留工程师，形状如下）：`DocumentNode` 由 interface 改为按 `type` 判别的联合——11 个同形状成员＋AttachmentNode＋TableNode；`AttachmentNode/TableNode` 改为 extends 共享基形状（不能再 extends 联合类型）。**运行时字段与取值零变化**。
- 编译约束在位：`strict: true`、`noUnusedLocals: true`、`noFallthroughCasesInSwitch: true`、`verbatimModuleSyntax: true`（tsconfig.app.json）。
