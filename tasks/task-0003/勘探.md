### 待办-0020：build:single Windows 失败

- package.json:9 `"build:single": "tsc -b && SINGLE_FILE=1 vite build"` —— `SINGLE_FILE=1` 前缀赋值为 Unix shell 语法，cmd 下被解释为执行名为 `SINGLE_FILE=1` 的命令而失败。
- vite.config.ts:8 `const isSingleFile = !!process.env.SINGLE_FILE` —— 模块顶层读环境变量；影响 base(:12) 与插件二选一（:19-52 单文件插件 vs PWA）。
- 本机环境实测：`npm config get script-shell` → `null`（即 Windows 默认 cmd）；项目无 .npmrc、用户级无 .npmrc（全新落点无冲突）；bash 实际路径 `C:\Program Files\Git\usr\bin\bash.exe`，另 PATH 中有 `C:\Windows\System32\bash.exe`（WSL 入口——裸名 `bash` 存在解析到 WSL 的歧义风险）。
- **CI 事实（.npmrc 方案的关键影响面）**：
  - .github/workflows/deploy.yml:19,34 `runs-on: ubuntu-latest`，:27 跑 `npm run build`
  - .github/workflows/release.yml:13 `runs-on: ubuntu-latest`，:23 跑 `npm run build:single`
  - 项目级 .npmrc 入库后对所有平台生效：若写 Windows 绝对路径 → ubuntu 上 spawn 该路径失败 → **两条 CI 全挂（deploy 是生产部署链路）**；若写裸名 `bash` → ubuntu 可用，但 Windows 端依赖贡献者 PATH 含 Git Bash（Git for Windows 默认 PATH 选项不含 bash.exe）且有解析到 WSL bash 的风险。
  - gongwen-docker/Dockerfile 基于 `nginx:stable-alpine3.21-perl` 且仅 COPY dist（:11 注释「需要先在项目根目录运行 npm run build」）——**镜像内不执行 npm scripts，alpine 无 bash 不构成影响**。
- 其余 npm scripts（dev/build/lint/test/preview）均为简单命令＋`&&`，bash/cmd 双兼容——换 script-shell 后语义不变。
- 备选方案事实（与预裁字面方向不同，仅供裁定）：vite 原生 `--mode single`（`vite build --mode single`）＋ vite.config.ts 改函数式 `defineConfig(({ mode }) => …)` 读 mode——零环境变量、天然跨平台、CI 零改动、无新依赖（红线不破）。代价：vite.config.ts 从对象式改函数式（约 2 行结构变化）。仓库已有 .env.development/.env.example，无 .env.single 文件，`--mode` 加载不产生副作用。
