## 裁定1｜0020 改道：vite --mode single（选项B），弃 .npmrc 方案（条款4 按本裁定实施）

**用户预裁**「优先 .npmrc 设 script-shell 方案，避免新依赖」——其**实质目标**＝修好 build:single＋不引新依赖。勘探新证据使 .npmrc 方案（条款4 落定的方向A）出现**不可验证的生产风险**：

1. 项目 .npmrc 写 Windows 绝对路径 → deploy.yml:27（生产部署链路）与 release.yml:23 均在 ubuntu-latest 跑 npm run → **两条 CI 必挂**；写裸名 `bash` → Windows 贡献者 PATH 不含 Git Bash 时本地 scripts 全挂＋WSL 解析歧义。
2. 方案A 的配套修复＝改 2 个 CI workflow 文件——**夜班禁止 git push，CI 改动无法实跑验证**，带未验证改动进生产部署链路违背「工程修复」意图。
3. 方案B（`vite build --mode single`）同样满足实质目标：零新依赖（vite 原生）、天然跨平台（无环境变量前缀）、CI 与贡献者零影响；代价仅 vite.config.ts 改函数式约 2 行结构。

**实施口径**：
- package.json:9 改 `"build:single": "tsc -b && vite build --mode single"`。
- vite.config.ts 改函数式 `defineConfig(({ mode }) => …)`，`isSingleFile = mode === 'single' || !!process.env.SINGLE_FILE`——**双入口**：`SINGLE_FILE=1 npx vite build`（AGENTS.md 既有记录命令）保持可用，零文档失实。
- build.target/cssTarget chrome78 红线不动。

**方案三问**：行为＝build:single 命令跨平台可执行、产物语义等价（同一 isSingleFile 分支）、既有 SINGLE_FILE=1 入口不变；验证＝Windows 本机 npm run build:single 产出单文件 dist/index.html＋SINGLE_FILE=1 npx vite build 等价＋npm run build 不受影响（三条全本机可验，不依赖 CI push）；回滚＝git revert 单提交，无可逆面。
