## 四、参考仓方法论映射（只读参照，不引代码）

dsh-tool-hongtou（README.md + lib/ 结构）：两阶段解耦（LLM 结构化 JSON → schema 校验+清洗+重试+确定性回退 → 确定性排版渲染+生成后断言终检），版式单一真值（document-skeleton.xml 模板，样式全在模板）。

对本项目的映射：
- 本项目已有「结构化中间表示」雏形 = GongwenAST（相当于其阶段一 JSON），**缺的是阶段二的确定性排版决策层**——即「AST+配置 → 版式决策」这一步现在被两个渲染引擎各自吞掉。
- 「版式单一真值」→ 决策层输出的中间表示是唯一真值，预览与导出退化为纯渲染器（本项目对应物是渲染器无关的 LayoutTree，而非 XML 模板）。
- 「断言终检」→ 行为保持的验收手段：对导出产物做结构断言（docx Document 序列化快照），对决策层输出做输入输出快照。
- 待办-0006/0008（AI 管线三级降级、AI 起草两阶段）与本次重构不同链路，但 0008 将来会**消费**决策层的稳定接口——决策层接口设计需为其留位，不为其实现。

## 同构与复用判定（横向必答）

**问题：「要造的排版决策层，是不是库中已有者的第二实例？」**

① **库内同构兄弟**：判定**是——且不止一个**。「AST+配置→排版决策」当前有**三份平行实现**（逻辑形状相同：同一条链路、同一类输入 AST+Config、同一个动作「决定字体分段/缩进/空行」）：
- 预览渲染：A4Page.tsx（renderHeadingX/splitAttachmentTextForPreview/getNodeStyle/calculateSignatureIndentEm）；
- 预览度量：Preview.tsx（getNodeStyle 副本+节点遍历副本）；
- 导出：docxBuilder.ts + styleFactory.ts（splitHeadingSentence/splitHeading3Text/splitTimeColonText/splitAttachmentText/getParagraphStyle）。
但「决策层本身」（独立的、渲染器无关的中间层）**不存在**——它不是第二实例，而是把三处既有同构收敛为第一实例。

② **待办池平行未来**：已读池（ctl backlog list，8 条）。待办-0001~0005 是该层缺位的**症状**而非平行需求；待办-0006（AI 校对降级+断言）、0007（docx 导入）、0008（AI 起草）链路不同，非同构。其中 0008 将来消费决策层接口（前置依赖，非平行竞争）。

**结论：判「否」（新层是第一实例，非第二实例），故无「就地 vs 抽象」双选项分叉。** 唯一上报的落点分叉是**已知偏差的处理策略**（详细需求【待澄清】Q1）：决策层输出统一真值后，预览/导出五项已知不一致（§3.6）如何在不违反「行为严格保持」的前提下安放——方案 A（偏差开关：真值统一+每项偏差一个开关默认保持现状，后续逐项翻转收敛）vs 方案 B（双轨决策：决策层先输出带渲染器标签的两轨结果，先同构后统一）。此分叉决定决策层接口形状，交技术负责人裁定。
