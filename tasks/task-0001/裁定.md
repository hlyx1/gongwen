## §一 决策层接口形状（Q1＝方案A：统一真值＋显式偏差开关）

新建 `src/layout/` 排版决策层输出**统一真值**；五项已知预览/导出偏差（勘探.md §3.6，对应待办-0001~0005）各设一个**显式偏差开关**，集中定义于决策层一处，默认值＝现状行为；决策层按开关产出各渲染器的最终决策。重构完成后，偏差修复＝晋升对应待办并翻转开关，偏差从隐性散落变显性集中可审计。

- 被否：方案B（决策层输出带渲染器标签的双轨结果）——把双轨病灶固化进新接口，统一被无限期推迟；五项之外的所有决策仍要维持"两轨对齐"假象，违背单一真值目标。
- 三问：行为保持（开关默认＝现状）／验证（决策层快照对五项偏差各断言两渲染器现状输出不变）／回滚（开关翻转即回，无数据面）。

## §二 行为保持验收口径（Q2＝方案A：结构级一致）

- 导出：docx 库 Packer 序列化产物（word/document.xml 等核心部件）结构快照，重构前后逐字段一致，快照文件入库；
- 决策层：输入输出快照（AST＋Config → 决策中间表示）；
- 预览：DOM 结构与 className 断言＋分页边界（总页数、每页首行内容）一致；人工视觉走查兜底（条款4/5 人工步骤）。
- 被否：B 逐字节一致（zip 时间戳/压缩细节不可控，成本高且失败不可归因）；C 仅人工视觉（回归靠人眼不可持续）。

## §三 配置双轨合并方向（Q3＝方案C——初裁，待用户追认）

设置弹窗重构为单一「标题字体」区（每级标题一组：中文字体/英文字体/字号），度止基础区/高级区中 h1/h2 的重复入口；advanced 的 addressee/h3 扩展字段并入同区。localStorage（键 `docx-document-config-v2`）读时自动升级，两轨值冲突以 **advanced 为准**（字段最全、驱动导出——导出是公文最终效力产物）。

- 不可逆面（配置数据迁移）非 git 回滚答案：升级前将旧结构原样备份至 `docx-document-config-v2.backup-<时间戳>` 键；回滚＝清空新键、恢复备份键（或还原旧版代码后旧键仍可读）。
- 三问：行为改变＝仅「两轨冲突的历史自定义配置」合并后单侧变化（默认值两轨本就相同，标准路径零变化；条款6 验收含旧配置迁移人工确认）／验证（迁移单测＋人工确认）／回滚（备份键）。
- **初裁状态：单元6（配置合并）启动前向用户追认；否决则按新裁定改判，影响面仅单元6。**
